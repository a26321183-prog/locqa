# Методология

## 1. Как искали
Детерминированный конвейер без внешних API (стоимость обработки: **0 $**, время прогона двух языков ≈ 3 с).

1. **Парсинг.** ARB читается как упорядоченный список пар, поэтому повторяющийся `"@@comment"` не теряется; метаданные `@key`
   и служебные ключи (`currencySymbol`, `lang`, `description`-заметка разработчиков) отделяются от строк.
2. **Индексы по файлу:** частоты слов цели и источника, translation memory (исходник → переводы, только строки нужного
   алфавита), «хвосты»-вставки, повторяющиеся у разных коротких исходников.
3. **Детекторы** (по типам кейса) возвращают находку с `evidence` на русском — что именно не так и чем это подтверждается
   (число символов, найденный хвост, частоты слов, версия того же ключа в другом языке).
4. **Языковые профили** `kk` / `uz` (алфавит, формы множественного числа CLDR, шаблон аффиксов после плейсхолдера).
   Профиль выбирается явно; неизвестный язык получает нейтральный профиль, а не казахский.
5. **Ранжирование:** severity (high/medium/low) × confidence; по умолчанию в отчёт попадают находки с confidence ≥ 0.5.

### Узбекский
Тот же код, но: латиница как ожидаемый алфавит; кириллица (в т. ч. одиночные кириллические буквы внутри латинских слов,
например `daqiqа`, `Mashinaга`) → `orthography`/`wrong_language`; единый апостроф в `oʻ/gʻ` и тутуқ-белгисе; казахские буквы
в узбекском файле → «казахский текст»; аффиксы после плейсхолдера (`{x}ga`) → `suffix_harmony`; глоссарий берёт колонку `uz`.

## 2. Как исправляли
* **Автоматически — только механические правки:** вернуть скобки `{time}`, исправить искажённое имя плейсхолдера, заменить
  визуально похожие буквы, исправить казахскую букву по частотам слов (`кұру → құру`), убрать вставленный хвост
  («Жеңіс режимін қосу және жалғастыру» → «Жеңіс»), взять уже существующий перевод того же исходника из этого же файла.
* **Вручную (`fixes/kk_curated_fixes.csv`):** отсутствующие ключи, узбекский/английский/португальский текст в казахском файле,
  непереведённые предложения, строки с аффиксом после плейсхолдера (переформулированы так, чтобы после `{…}` стоял целое
  слово, а не окончание), смысловые ошибки (`Баланс → қолма-қол ақша`, `Брак → Заңға бағынушылық`, «изменить регион» → «Тапсырманы…»).
  Тексты подготовлены ассистентом ИИ (Claude) и **не проверены носителем**.
* Массовой перегенерации через LLM нет: изменено **124 строки из 5 480** (kk), из них 12 — добавленные недостающие ключи;
  48 правок механические, 76 — ручные. Узбекский (бонус): 97 механических правок (в основном апострофы и смешанные буквы).

## 3. Сколько строк прошло через носителя
**0 из 124.** У всех изменённых строк `reviewed_by_human = false`. Носителя в команде не было; вместо ложных отметок подготовлены
`review_kk.html` / `review_kk.csv` и команда `apply-review`, которая проставляет `true` только после явного решения человека.
Строки без проверки не должны учитываться как проверенные.

## 4. Совместимость с `flutter gen-l10n`
Flutter в среде разработки не запускался. Вместо этого `locqa validate` проверяет то, на чём `gen-l10n` обычно падает: валидный JSON,
каждый ключ есть в шаблоне, набор плейсхолдеров равен русскому, баланс скобок/кавычек ICU, нет «осиротевших» `@key`.
Результат: `intl_kk_fixed.arb` — единственные замечания — два ключа `more`, `inStore`, которые были лишними в исходном файле
(не наши правки). Отметки проверки хранятся в пользовательском атрибуте `x-locqa` внутри `@key`.

## 5. Метрики и честные ограничения
* Список ~100 подложенных ошибок у организаторов, поэтому **recall мы не измеряли**; по найденным типам видно, что покрыты
  плейсхолдеры (12), потерянные ключи (13), чужой язык (12), «вода» в коротких строках (10), опечатки-аналоги букв (≈25), аффиксы (8).
* Смысловые ошибки перевода (подмена слова на другое слово) офлайн ловятся только косвенно (`inconsistent_term`, числа,
  глоссарий). Для них нужна проверка носителем или опциональная LLM-проверка (в этой версии не реализована — без ключа).
* `same_as_source` для коротких слов даёт заимствования (`Кабинет`, `Департамент`): они помечены medium/low с объяснением,
  часть из них легитимна — решает носитель. Игровой сленг (`варн`, `мут`, `фура`, `ГК`) заложен в глоссарий.
* `inconsistent_term` — самый шумный тип (синонимы вроде `сыйлық/жүлде/сыйақы`); они имеют severity low.
* Глоссарий построен по данным файлов и описанию кейса, статус `proposed` — не подтверждён носителями.
